# Phase 9 frozen evaluation protocol

This document fixes the evaluation rules before any odd-indexed formula body is opened. The task is the Phase 0 task: exact rational weighted model counting on the 2024 Model Counting Competition Track 2 archive. This is a direct solver comparison, not an evaluation of the broader XAI architecture or the synthetic certificate verifier.

## Data and split

Use the archive snapshot whose MD5 is `1c7e6279eaf29bf3731cebe07eedf107` and SHA-256 is recorded by the freeze manifest. Its 200 indexed members are split by the existing even/odd rule: the 100 even-indexed members are the development set and the 100 odd-indexed members are the final set. The public-only Phase 0 audit establishes 98 eligible even members; `random_196` and `random_198` fail the exact rational weight-sum rule and are excluded before any solver scoring. Do not round or renormalize weights. Apply the same exact eligibility rule to odd members.

Before scoring any odd member, verify the frozen source, options, metrics, data snapshot, and analysis plan, then run the cross-split leakage audit. Compare each even/odd pair by (1) SHA-256 of the exact decompressed formula bytes, (2) the Phase 0 canonical formula SHA-256, (3) normalized exact `c r` provenance tags, and (4) Jaccard similarity of distinct non-tautological clause sets at or above 0.95 when variable counts match. Any related eligible odd record is removed from final-test claims and reported with its public counterpart and relation type. Missing provenance remains unknown dependence, not evidence of independence. No odd body may be used for tuning, choosing options, or revising this plan.

XZ is transport only. Each selected member is decompressed once to a temporary file; the original decompressed formula bytes are passed unchanged to every compared solver. No raw instance body is included in committed results.

## Systems and fixed options

The primary baseline is [Ganak](https://github.com/meelgroup/ganak) v2.7.0 at commit `e8f51841832efbbad4c1dc30e7e628ea39e8eec6`. Use exact rational mode (`--mode 1`), deterministic hashing (`--prob 0`), seed `1`, the weighted MCC cache setting (`--maxcache=16000`), exactly one thread (`--threads 1`), and verbosity `0`. The binary and fetched dependency revisions are hashed in the freeze manifest. Build the pinned source in Release mode. On this Ubuntu package set, FLINT’s `pkg-config --libs flint` omits `-lflint` even though the Ganak CLI directly calls FLINT symbols, so supply an explicit `-lflint` link flag as a build-only workaround (`-DCMAKE_CXX_STANDARD_LIBRARIES=-lflint`). This does not change runtime solver options or counting semantics. Record the final build command and dependency commits; do not edit pinned Ganak source.

The candidate is the directly invoked C++20 `xai_wmc_solver`, with its declared parser limits and solver options: 10,000,000 recursive nodes, 600,000 ms internal search timeout, and depth 4,096. Compare the full configuration against three predeclared one-at-a-time ablations: unit propagation disabled, component decomposition disabled, and occurrence-based branching disabled. No synthetic certificate is supplied or interpreted as production verification.

Each solver attempt runs sequentially, pinned to one logical CPU, with a 600-second wall-time ceiling including solver parsing, a 601/602-second soft/hard CPU limit, and a 4-GiB resident-memory ceiling monitored per process group. The runner records wall time, sampled CPU time, sampled peak RSS, sample counts, process status, output hashes, exact count when present, and raw stdout/stderr; CPU/RSS are `null` if the process exits before any sample. The 10-ms RSS polling can observe a brief overshoot before termination; report any attempt at or above the ceiling as a memory-limit outcome, not as a count. A resource kill, timeout, parser error, unsupported input, or missing output is never an answer.

## Outcomes and analysis

The primary correctness outcome is exact rational WMC equality between each successful XAI configuration and successful Ganak output on the same formula. Counts are parsed as arbitrary-precision fractions; no floating-point tolerance is used. For any eligible benchmark formula with at most 20 declared variables and `2^nvars × literal_occurrences ≤ 50,000,000`, also run an independently parsed exact exhaustive enumeration; compare every successful solver count with it. SAT/UNSAT status text is retained only as auxiliary output: zero literal weights can make solver status labels differ even when both exact WMC outputs are zero. Such labels are not a correctness criterion. Any exact-count mismatch against Ganak or an applicable independent oracle stops the split’s run immediately and invalidates the exactness claim. An XAI count is called **directly verified** only when its successful exact rational count equals Ganak’s successful exact rational count for that exact input. The Phase 8 in-process synthetic verifier does not contribute evidence.

The primary bounded-utility outcome is the count and fraction of exact-weight-eligible records each system completes within the fixed limits. Preserve separate categories for solved exact, timeout, memory limit, solver resource limit, parser error, unsupported input, nonzero exit, and unrecognized output. Report the number of directly matched/verified counts and the exact-match fraction among pairs where both systems complete. Report finite-set totals, descriptive completion fractions, median and maximum wall time, and observed peak RSS. These curated challenge archives are not probability samples; do not add population confidence intervals, significance tests, speedup targets, or generalization claims. Keep all exclusions, failures, and per-instance results.

There are no gold outcome labels and no calibration split. Brier/log scores, reliability, calibration, conformal coverage/set size, predictive accuracy, and selective-risk curves are not estimable for this WMC task. Report them as not applicable rather than borrowing synthetic Phase 6 fixtures. Entity identity, temporal/domain shift, and human-source dependence are outside the formula-only WMC input contract. Task-relevant stress cases are direct exact-count fixtures for weighted disjunction, duplicate-clause invariance, paired variable-renaming invariance, omitted-weight/#SAT defaults, contradiction/UNSAT, satisfiable zero-WMC, malformed/corrupted input, unsupported projected input, and bounded resource exhaustion. These test formula semantics and do not claim to simulate identity errors or temporal shift. Existing parser and solver boundary tests are also part of the verification record.

## Stopping and claims

Run all exact-weight-eligible records and all four candidate configurations plus Ganak unless a directly observed count mismatch occurs, in which case stop immediately. Do not repair a disappointing final-set result by changing options. Preserve the freeze manifest, cross-split audit, run JSONL, summaries, validation log, stress results, and exact solver/dependency hashes.

For the practical threshold, a **nontrivial record** is one with at least two declared variables and one or more declared clauses. A passing practical result requires at least one such eligible formula to complete in both the full candidate and Ganak within limits with directly equal exact rational counts, no mismatch on any attempted instance, and truthful noncompletion statuses. A Phase 9 completion report must also disclose any missing record, excluded leakage group, resource-control deviation, dependency/build limitation, or interrupted run. Claims are bounded to directly compared exact WMC results on the named archive, split, frozen implementation, and resource limits. No benchmark calibration, production certificate, broader-architecture, representative-workload, or deployment claim is made.
